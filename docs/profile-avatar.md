# Photo et avatar du profil

Depuis le profil, le compte choisit une console, un genre/univers et un style graphique, puis une photo de visage. L'application affiche immédiatement la photo et l'envoie à `POST /api/profile/avatar` avec la session et les choix dans les en-têtes `X-Avatar-Platform`, `X-Avatar-Genre` et `X-Avatar-Art-Style`. Le serveur valide ces valeurs dans son catalogue, redresse l'image, la limite à 1024 px de côté et l'enregistre en JPEG compressé. Une version privée est créée avec les trois choix ; `profile_avatars` pointe vers la version courante. Les anciennes versions restent dans `profile_avatar_versions` et chaque changement est inscrit dans `journal_entries`.

Le worker traite les versions en attente par lots de deux. Il envoie uniquement la photo source et un prompt construit à partir des choix à l'endpoint OpenAI Images Edits, modèle `gpt-image-2.5-sunburst`. Le prompt demande un personnage de jeu vidéo reconnaissable dans le rendu choisi, sans texte, logo ni personnage d'une franchise existante. Si la console et le style graphique se contredisent, le style prime et la console guide la palette et les textures. La réponse est ramenée à 512 × 512 px en JPEG compressé avant stockage. Aucun nom, email ou profil sportif n'est envoyé avec la photo. Le traitement reprend après un redémarrage ; une génération interrompue depuis plus de quinze minutes peut être reprise avec les mêmes choix. Une nouvelle photo devient immédiatement la version courante et ne peut pas être remplacée par le résultat d'une ancienne génération.

`GET /api/profile/avatar` renvoie `pending`, `processing`, `ready` ou `failed`, avec les chemins privés de la photo source et de l'image générée. Le mobile conserve la photo choisie pendant la génération, interroge le statut lorsqu'il est sur l'écran et affiche ensuite l'avatar généré. `POST /api/profile/avatar/retry` relance une version en échec sans réimporter la photo. Les images sont lues via `GET /api/profile/avatar/images/:id/:kind` et restent protégées par la session ; le cache mobile est vidé à la déconnexion.

Appliquer `cd api && npm run migration:run` avant usage, y compris la migration `ProfileAvatarChoices1791500000000` qui ajoute les choix aux versions existantes avec les valeurs par défaut. Le serveur réutilise `OPENAI_API_KEY` ; sans clé ou si l'accès au modèle n'est pas accordé, la photo source reste visible et l'utilisateur peut réessayer après correction. Les tests simulent la réponse de génération : ils ne font aucun appel payant.

Sur un poste qui partage le même dépôt entre Windows et WSL, `sharp` charge un binaire propre au système qui lance l'API. Si `npm start` sous Windows indique `Could not load the "sharp" module using the win32-x64 runtime`, exécuter `npm install --include=optional sharp` depuis PowerShell dans `api/`, puis relancer l'API. Les installations npm faites ensuite depuis WSL peuvent nécessiter de répéter cette commande côté Windows.
